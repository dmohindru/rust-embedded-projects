# SSD1306 Driver Development Notes (Rust + embedded-graphics)

## Goal

Write a reusable Rust device driver for an SSD1306 128×64 OLED using I²C
and integrate it with `embedded-graphics`.

# I²C Protocol Essentials

## Slave Address

The SSD1306 supports two 7-bit addresses:

- `0x3C`
- `0x3D` <--- This one I own

Which one is used depends on the SA0 pin (often wired permanently on the
module).

## Control Byte

Every I²C transfer begins with a control byte.

### Command Transfer

    Control Byte = 0x00

    Co = 0
    D/C = 0

    Following bytes are commands.

### Data Transfer

    Control Byte = 0x40

    Co = 0
    D/C = 1

    Following bytes are display data.

For almost all drivers, `Co = 0` is sufficient.

### Important text

```text
After the transmission of the slave address, either the control byte or the data byte may be sent across
the SDA. A control byte mainly consists of Co and D/C# bits following by six “0” ‘s.
a. If the Co bit is set as logic “0”, the transmission of the following information will contain
data bytes only.
b. The D/C# bit determines the next data byte is acted as a command or a data. If the D/C# bit is
set to logic “0”, it defines the following data byte as a command. If the D/C# bit is set to
logic “1”, it defines the following data byte as a data which will be stored at the GDDRAM.
The GDDRAM column address pointer will be increased by one automatically after each
data write.
```

# Commands

Commands may be:

### Single byte

    0xAE
    Display OFF

### Multi-byte

    0x20
    0x00

    Set Memory Addressing Mode
    Horizontal Addressing Mode

or

    0x21
    0x00
    0x7F

    Set Column Address

The SSD1306 command decoder knows how many argument bytes belong to each
command.

---

# GDDRAM Layout

Display size:

    128 × 64 pixels

Memory:

    8 Pages

    ×

    128 Columns

    =

    1024 Bytes

Each page is:

- 8 rows high
- 128 columns wide

Each byte represents one vertical strip of eight pixels.

For Page 0 / Column 0:

    bit7 -> (0,7)
    bit6 -> (0,6)
    ...
    bit1 -> (0,1)
    bit0 -> (0,0)

Moving to the next byte moves to the next column.

    Column 0
    ↓

    Column 1
    ↓

    Column 2

---

# Pixel Address Calculation

    page   = y / 8
    bit    = y % 8
    column = x

    index = page * 128 + column

Setting a pixel:

```rust
buffer[index] |= 1 << bit;
```

# Important Commands

## Multiplex Ratio (A8)

Determines how many COM outputs are scanned.

128×64 display:

    A8
    3F

Mostly initialization only.

---

## Segment Re-map (A0/A1)

Changes mapping between GDDRAM columns and physical SEG pins.

Effect:

- Horizontal mirror

Used to compensate for module orientation.

---

## COM Scan Direction (C0/C8)

Changes order of COM scanning.

Effect:

- Vertical mirror

Combined with Segment Re-map can rotate the display 180°.

Cannot perform 90° rotation.

---

## Display Offset (D3)

Shifts where scanning begins on the physical panel.

Useful for:

- Different panel layouts
- Mechanical alignment

Normally zero.

---

## Clock Divide / Oscillator (D5)

Controls internal SSD1306 timing.

Not related to I²C speed.

Does **not** make application animations faster.

Initialization only.

---

## COM Pins Configuration (DA)

Describes how the OLED glass is wired.

Initialization only.

---

# Hardware Acceleration

The SSD1306 does **not** accelerate graphics.

It cannot draw:

- Lines
- Rectangles
- Circles
- Text

Those are generated by `embedded-graphics`.

The only real hardware acceleration is:

- Horizontal scrolling
- Vertical scrolling

The controller scrolls by changing address generation internally.

---

## 2. Maintain Framebuffer

```rust
buffer: [u8; 1024]
```

The framebuffer is the source of truth.

---

## 3. Implement DrawTarget

`draw_iter()` updates only the framebuffer.

It should **not** perform I²C writes.

---

## 4. Flush

`flush()` uploads framebuffer to SSD1306.

Recommended using Horizontal Addressing Mode.

Commands:

    Set Column Address

    0x21
    0x00
    0x7F

    Set Page Address

    0x22
    0x00
    0x07

Then:

    Control Byte = 0x40

    buffer[0]
    buffer[1]
    ...
    buffer[1023]

The SSD1306 automatically increments:

    Column 0

    ↓

    Column 127

    ↓

    Page 1

    ↓

    ...

    ↓

    Page 7

# Suggested Driver API

```rust
pub struct Ssd1306<I2C> {
    i2c: I2C,
    buffer: [u8; 1024],
}

impl<I2C> Ssd1306<I2C> {
    pub fn new(...) -> Self;

    pub fn init(&mut self);

    pub fn flush(&mut self);

    fn write_command(&mut self, cmd: u8);

    fn write_commands(&mut self, cmds: &[u8]);

    fn write_data(&mut self, data: &[u8]);
}
```

Implement:

```rust
embedded_graphics_core::draw_target::DrawTarget
```

where `draw_iter()` updates the framebuffer.
